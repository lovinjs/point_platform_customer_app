## 构建

在消费者端项目根目录执行：

```bash
npm run type-check
npm run build:h5:staging
```

预发布配置位于 `.env.staging`，仅包含可公开的前端配置：

- `VITE_RELEASE_CHANNEL=staging`：门店、我的和登录页展示预发布测试提示。
- `VITE_ICP_FILING_NUMBER`：上述三个页面底部展示链接到工信部备案系统的备案号，仅 H5 显示。
- `VITE_API_BASE_URL=`：通过同域名 `/api` 请求，由 OpenResty 按白名单代理到后端。
- `VITE_WECHAT_AUTH_ENABLED=true`：2026-10-11 用户确认后端环境配置和健康检查完成后，已仅为 staging 开启微信授权。最初上传的 2026-10-10 包仍为 `false`；必须上传本次新包才能启用页面上的登录按钮。本地开发和普通生产配置仍为 `false`。

构建产物为 `dist/build/h5-staging`，不会覆盖普通构建的 `dist/build/h5`。本地 HBuilderX 开发仍使用原开发环境配置。

不要将 AppSecret、AccessKey、JWT 密钥或数据库密码写进任何 `VITE_` 环境变量。环境变量在构建时写入前端产物，不是在服务器上传 `.env` 后动态读取。

## 上传与回滚

1. 上传前记录源码版本、构建时间及包的 SHA-256，保留上一份已验证的包。未提交代码构建的包要明确记录包含未提交改动。
2. 在网站根目录以外备份原站点内容。只上传构建产物，不上传源码、`node_modules`、`.env` 或压缩包本身到可公开下载的位置。
3. 将 `dist/build/h5-staging` 内的内容放到网站根目录，不要再套一层 `h5-staging` 文件夹。根目录应直接包含 `index.html`、`assets` 和 `static` 等构建内容。
4. 不删除或覆盖证书验证目录 `/.well-known/`，以及后续微信提供的域名校验文件。
5. 更新时先上传新的静态资源，最后替换 `index.html`；不要先清空整个网站。保留上一版哈希资源可降低已打开页面更新后的加载失败风险。
6. 回滚时恢复上一份已验证包的入口文件和对应静态资源；不要回滚或清空数据库。

第一次上传之前先完成消费者 API 代理及公网边界验收，具体片段和只读检查见后端项目 `docs/h5-staging-deployment.md`。当前不增加网站密码或 IP 白名单；证书校验路径和后续微信域名校验文件仍按校验需要保留可达性。
